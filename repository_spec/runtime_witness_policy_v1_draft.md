# Runtime Witness Policy v1 Draft

Status: draft policy for source-as-oracle user-run checking

This policy defines how runtime local DB/checker execution should treat witness data. It does not implement runner changes, run DB engines, run checkers, compute official metrics, or update retained evidence.

## Data Profile Policy

`data_profile.yaml` is optional in case package v2.

It may be:

- generated from schema/load assets
- stored externally under evidence
- stored as lightweight case-local witness metadata
- omitted when runtime execution can derive the needed context

Missing `data_profile.yaml` must not block local user-run execution if source SQL execution and checker configuration are available.

## Correct Result Policy

`correct_result.csv` is optional.

It may be retained as a static witness when public-safe and available, but it is not required for local user-run checking.

No task may fabricate a correct result. If a static correct result is unavailable, the manifest or audit should record that status.

## Runtime Source SQL Result As Oracle

For user-run DB/checker execution, source SQL is the default oracle:

1. set up the declared schema context
2. execute `sql/source.sql`
3. execute candidate SQL
4. normalize both result artifacts according to checker config
5. compare source result to candidate result

This produces local diagnostic exact/mismatch status only. It is not an official metric by itself.

## Source Result vs Candidate Result Comparison

The checker consumes:

- `source_result`
- `candidate_result`
- checker config
- normalization config
- compare config
- case metadata
- engine id

If source execution fails, exactness must not be inferred.

If candidate execution fails, exactness must not be inferred.

If checker config is missing or unsupported, exactness must not be inferred.

## Retained Static Witness

Static witness artifacts may remain under optional retained-artifact surfaces when available and separately authorized. They are useful for:

- audit review
- retained control evidence
- package validation
- reproducibility notes

They are not required for runtime source-as-oracle checking.

Clean v2 does not require case-local `evidence/` or top-level `evidence/cases/<POOL>/<CASE_ID>/` static witness/evidence packages. When source-as-oracle execution and checker configuration are available, runtime witness evidence should be regenerated by validation/checker/report scripts rather than required as committed static evidence.

## Fail-closed Behavior

The runner/checker must fail closed when:

- source execution is unavailable
- declared schema cannot be resolved
- checker config is missing
- normalization or compare config is required but missing
- unsupported checker semantics are encountered

Fail-closed means recording local diagnostic status and failure bucket, not guessing semantic equivalence.

## Boundaries

Runtime witness comparison does not compute official Generation Rate, Execution Coverage Rate, Result Consistency Rate, timing metrics, paper tables, retained evidence, reports/results, or leaderboard output.
