# Runs Retention Policy v1

Status: draft policy for clean public release migration

Scope: SQL-RewriteBench case packages, retained run artifacts, sanitized public evidence, and private/original archive mappings.

This policy does not create new scientific evidence. It does not alter Common-core membership, denominators, paper tables, benchmark claims, admission status, or case results.

## 1. Policy Goals

The public release must preserve traceability without exposing local maintainer environment details. Case-local `runs/` directories are treated as legacy retained evidence surfaces until every artifact has a retention mapping.

The policy goals are:

- keep evidence visible and role-aware;
- prevent deletion without retention mapping;
- prevent raw local path traces from appearing in public retained evidence;
- distinguish public-safe evidence from original/private evidence;
- support external runners without making generated run outputs part of the default case package;
- record all exceptions in `evidence/runs_retention.yaml`.

## 2. Definitions

`runs/`: legacy retained evidence surface. Existing case-local run artifacts may contain control validation, plan observability, hard-negative closure, source/positive/negative outputs, method outputs, local runtime residue, or ambiguous historical evidence.

`public retained evidence`: evidence that can be included in the public release without exposing local paths, credentials, prompt/API traces, raw logs, or private runtime state.

`sanitized public copy`: a public artifact derived from an original evidence artifact by removing or replacing release-hygiene-sensitive fields while preserving the evidence-bearing content needed for review.

`private/original archive`: a non-public or separately controlled location for original raw artifacts that contain local paths, logs, or other release-hygiene risk but remain needed for traceability.

`external runner output`: output that can be regenerated by a public runner and should not be committed as default case-local evidence unless explicitly retained.

## 3. Allowed Retention Classes

Use these classes in retention mappings:

- `public_safe_keep`: artifact can be public as-is.
- `sanitized_public_copy`: public release should include a sanitized copy while retaining the original through mapping.
- `private_archive_only`: artifact should not be public by default; preserve only through private/original archive mapping.
- `external_archive_reference`: artifact is retained outside the case package and referenced by stable archive metadata.
- `regenerable_by_external_runner`: artifact should be produced by documented runner commands, not checked into the default public case package.
- `manual_review_required`: artifact cannot be safely classified by static inspection alone.

No class authorizes deletion by itself.

## 4. No-Delete Rule

Do not delete, truncate, rewrite, bulk-move, or silently omit `runs/` artifacts until a case has a reviewed `evidence/runs_retention.yaml` mapping.

The mapping must record:

- original legacy path;
- proposed public path, if any;
- proposed archive path, if any;
- evidence role;
- risk categories;
- sanitization/redaction fields, if any;
- do-not-delete status;
- human approval status when needed.

## 5. Spark Plan Local-Path Policy

Spark plan files may include maintainer-local paths such as `file:/home/...`, temporary Spark warehouse paths, WSL/host-specific paths, or local scratch directories. These paths must not appear in public retained evidence.

When a Spark plan artifact is otherwise evidence-bearing:

1. keep the original legacy artifact through mapping;
2. create a sanitized public copy in a later migration step;
3. preserve plan semantics, operator names, predicates, joins, projections, and failure/observability content;
4. redact only local-path or runtime-environment fields;
5. record the original-to-sanitized relationship in `evidence/runs_retention.yaml`;
6. place raw originals in private/original archive or keep them in legacy source until an archive decision is made.

This task only defines the policy. It does not sanitize or copy any plan files.

## 6. Result-Check and Log Reference Policy

Some `result_check.json` files may reference raw stdout/stderr logs. The public release should not expose raw log paths by default.

For result-check files with stdout/stderr references:

- keep a sanitized or summarized public result-check record;
- preserve pass/fail/mismatch/control-validation meaning;
- redact raw stdout/stderr path fields or replace them with stable archive references;
- retain original raw result-check/log references through private/original archive mapping;
- record the relationship in `evidence/runs_retention.yaml`.

Raw logs should not be published unless separately reviewed and approved.

## 7. Public vs Private Evidence

Public evidence should be sufficient for reviewers to understand the retained evidence role and reproduce or validate the claim boundaries. Private/original archive evidence preserves raw traceability where public hygiene prevents direct publication.

Public evidence must not include:

- raw local filesystem paths;
- WSL or host-specific path traces;
- raw stdout/stderr log paths by default;
- prompt, assistant, API, token, or model-output traces;
- database credentials or private service endpoints.

Private/original archive mappings must not be used to hide failed, unsupported, mismatched, no-op/source-like, checker-failed, timing-missing, or missing-artifact states.

## 8. External Runner Policy

New default execution outputs should be produced outside case packages by documented external runners. Case packages may reference commands, expected outputs, and retained evidence summaries, but should not accumulate new local `runs/` residue.

Regenerable outputs should be classified as `regenerable_by_external_runner` and linked to runner commands once those commands exist.

## 9. Human Approval Requirements

Human approval is required before:

- publishing a sanitized derivative of a raw evidence artifact;
- moving original artifacts to private/external archive;
- omitting an original raw artifact from the public package;
- changing any evidence role;
- deleting any artifact previously listed in a no-delete list;
- publishing raw logs or raw local-path plan artifacts.

## 10. PORT Manual-Review Application

The approved PORT decision is:

- sanitized public copies should be kept for Spark plan evidence with local path traces;
- original legacy plan artifacts remain retained through mapping and may stay in private/external archive;
- raw local path traces must not appear in public retained evidence;
- `PORT_0024`-style stdout/stderr log references should be summarized or archived, not exposed raw by default.

Evidence-index normalization can proceed using preview mappings. Physical migration remains blocked for affected cases until sanitized public copies or archive mappings are implemented.
