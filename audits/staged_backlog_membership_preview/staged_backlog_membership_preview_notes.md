# Staged/Backlog Membership Preview Notes

Date: 2026-05-17

## Preview-only Boundary

This output is a human-review surface. It is not an official membership file and does not create `staged_v0`, `backlog_v0`, or `extended_v0` case sets.

## Why Official Files Are Not Created Yet

Official staged/backlog membership requires maintainer approval of criteria, reconciliation of the seven unregistered directories, and agreement on whether staged/backlog files are part of public v0 or post-release governance. Those approvals are not encoded by this task.

## Relation To Public Release v0

Public release v0 remains anchored on Common-core 40. The preview helps plan post-release or extended governance but does not add cases to the v0 main denominator.

## Denominator Boundary

Non-Common-core cases cannot enter the Common-core denominator because the paper-facing Common-core v0 denominator is fixed at 40 cases and 120 planned same-engine rows. Staged/backlog files, if later created, must explicitly state that they are not denominator changes.

## Human Approvals Needed

- Approve staged/backlog criteria.
- Decide how to handle each unregistered directory.
- Decide whether any manual-review case is duplicate, alias, scratch/private, defer, or backlog.
- Approve official membership file paths and schema.
- Approve migration eligibility criteria for later non-Common-core batches.

## Post-release Expansion Connection

This preview can seed post-release expansion planning after the clean Common-core v0 release path is stable. Expansion should proceed by bounded batches, retained-evidence mapping, public hygiene scans, and validator-backed canonical package migration.
