# Fail-Closed Policy

The prior MySQL/Spark PostgreSQL-dialect guard remains active.

Guarded forms:

- simple double-quoted identifiers for MySQL/Spark
- `DOUBLE PRECISION` for MySQL/Spark

If a target-dialect-aware runtime is not available or regresses to
PostgreSQL-dialect output, the adapter removes the executable candidate path and
records:

- `preflight_status = calcite_target_dialect_unsupported`
- `failure_bucket = no_candidate_sql`
- a target-dialect guard bucket such as
  `mysql_postgres_dialect_quoted_identifier`

In this bounded validation, MySQL and Spark candidates generated by the staged
runtime did not match the PostgreSQL-dialect guard. MySQL and Spark candidate
SQL used backtick quoting and reached DB execution where the row policy allowed
execution.

Rows that still fail closed:

- `PORT_0004` on all engines: no candidate emitted.
- `PORT_0024` on Spark: candidate emitted, but the user-run Spark
  target-reference/source-role policy remains unsupported.
